# burdaAI

burdaAI — собственная языковая модель организации Neuroslop League. Цель проекта — выпустить работоспособную модель с документированным и воспроизводимым обучением.

На момент подготовки спецификации репозиторий содержит только документацию. Реализация, результаты тестирования и результаты обучения в репозитории отсутствуют.

## Архитектура модели

Модель использует decoder-only Transformer. На вход подаётся последовательность идентификаторов токенов. Модель возвращает логиты для предсказания следующего токена на каждой позиции. Causal Attention позволяет каждой позиции учитывать себя и предыдущие позиции. Grouped-Query Attention (GQA) распределяет 16 голов запросов по 4 группам. В каждой группе четыре головы запросов используют общие ключи и значения.

| Параметр | Утверждённое значение |
| --- | --- |
| Тип модели | Decoder-only Transformer |
| Маска внимания | Causal Attention |
| Механизм внимания | Grouped-Query Attention (GQA) |
| Число слоёв | 20 |
| Размер скрытого представления | 2048 |
| Число голов запросов | 16 |
| Число голов ключей и значений | 4 |
| Промежуточная размерность FFN | 5632 |
| Контекстное окно | 4096 токенов |

При равном разбиении скрытого представления на головы размерность головы составляет 128. Контекстное окно ограничивает общее число токенов, доступных модели в одном контексте.

Выбор токенизатора, позиционного кодирования, нормализации и варианта FFN предстоит зафиксировать. Размер словаря и соглашения об идентификаторах специальных токенов зависят от выбора токенизатора. Программный интерфейс и зависимости будут документироваться по мере реализации.

### Проверка архитектуры

- Сверить конфигурацию и формы тензоров с таблицей. Проверить распределение голов запросов по группам KV.
- Изменить токены после выбранной позиции и проверить, что логиты на этой позиции и раньше совпадают в пределах численной погрешности.
- Проверить прямой проход на короткой последовательности и на последовательности из 4096 токенов. Поведение при превышении окна определить и проверить при реализации входного интерфейса.

## Обучение

Утверждён режим BF16 Mixed Precision. Операции, требующие повышенной численной точности, выполняются в FP32. Состояния оптимизатора хранятся в FP32.

Для запуска нужны реализация модели, токенизатор, подготовленные данные и среда с поддержкой выбранного режима точности. Состав критичных операций, алгоритм оптимизации, данные, программный стек и оборудование предстоит зафиксировать. Без этих решений оценка памяти и времени обучения остаётся открытой.

### Проверка обучения

- Проверить фактические типы данных для критичных операций и тензорных состояний оптимизатора после первого обновления.
- Выполнить короткий прогон с прямым и обратным проходами. Проверить конечность значения функции потерь и градиентов, а также обновление весов.
- Проверить сохранение и восстановление состояния обучения на коротком прогоне. Зафиксировать версии кода, данных и токенизатора, конфигурацию и окружение, необходимые для повторения запуска.
