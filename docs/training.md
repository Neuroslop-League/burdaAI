# C05. Обучение и контрольные точки

Цель — подтвердить запуск, обновление весов и восстановление на фактическом оборудовании. Известно о доступной видеокарте RTX с объёмом VRAM более 8 ГБ. Модель карты, точный объём и возможности вычислительного backend уточняются в C05.1. Профиль инференса на 1 ГБ из C01.4 относится к выпуску.

## Конфигурация запуска

| Группа | Что фиксируется |
| --- | --- |
| Окружение | Коммит, версии backend и драйвера, модель GPU и объём VRAM, CPU, RAM, способ запуска |
| Модель и данные | Конфигурация C01, манифест C04, версия токенизатора, параметры чтения и его seed |
| Оптимизация | Оптимизатор, learning rate, расписание, параметры регуляризации, число шагов, правило ограничения нормы градиента при его использовании |
| Память | Длина последовательности, размер микропакета, число микрошагов накопления, применение checkpointing активаций или выгрузки состояния при необходимости |
| Контроль | Частота метрик, валидации и сохранения, место хранения и критерий остановки |

AdamW предлагается для первого пробного запуска. Обучение и checkpoints реализуются на Python и PyTorch. Версии библиотек, алгоритм и параметры утверждаются после инвентаризации железа. Для сравнения вариантов привести измеренные пиковые VRAM/RAM, токены в секунду и время на шаг.

## Цикл и точность

1. Сверить идентификатор и размер словаря в конфигурации модели и манифесте. Собрать пакет с правым дополнением и выполнить прямой проход C03.
2. Для позиции `t` цель равна ID на `t+1`, если обе позиции действительны и переход разрешён C04. Выполнить сдвиг один раз. Использовать среднюю кросс-энтропию по действительным целям. При накоплении градиентов суммировать вклад по целям и нормировать на общее их число за шаг. Пакет без действительных целей считается нарушением контракта данных.
3. Выполнить обратный проход и обновление. BF16 Mixed Precision применяется к подходящим операциям. Критичные вычисления C01, кросс-энтропия и суммирование loss выполняются в FP32. Тензорные состояния оптимизатора хранятся в FP32. Нефинитные значения фиксируются с номером шага и конфигурацией.
4. Записать loss, число действительных целей, learning rate, время шага, пропускную способность и пики памяти. Валидацию проводить на фиксированных данных C04.

Для иллюстрации размера при 32 768 токенах получаются 968 968 192 параметра. Если параметры, градиенты и два момента оптимизатора занимают по четыре байта на параметр, их суммарный размер составляет около 15,5 ГБ до активаций и рабочих буферов. Эта оценка относится к указанной схеме размещения. При нехватке памяти C05.1 проверяет уменьшение микропакета и длины пробного входа, checkpointing активаций и выгрузку состояний в RAM либо определяет требования к другой машине. Сокращённый пробный вход сохраняет архитектурный лимит в 4096.

## Восстановление и приёмка

Контрольную точку сохранять после завершённого шага оптимизатора. Она содержит веса, состояния оптимизатора и расписания, номер шага, счётчики токенов, состояние чтения и генераторов случайных чисел, а также ссылки на конфигурацию и манифесты. Публиковать точку только после успешной записи и проверки читаемости. При несовместимом окружении, конфигурации либо манифесте запуск сообщает причину отказа.

- **C05.1.** Инвентаризировать RTX и провести проверку BF16. Зафиксировать пробную конфигурацию и бюджет памяти.
- **C05.2.** Сравнить loss со значением контрольного примера. Проверить типы критичных операций и состояний после обновления, конечность loss и градиентов и фактическое изменение весов.
- **C05.3.** На одной конфигурации сравнить непрерывный и возобновлённый прогон. Сверить следующий пакет, шаг, расписание и метрики в допуске, установленном до теста. Проверить отказ при повреждённой точке или несовместимом манифесте.
- **C05.4.** Передать C06 команду, конфигурацию, журнал, фактические замеры, контрольную точку и вывод о допустимом масштабе полного запуска. Принимающий повторяет пробный сценарий по инструкции.

### Подготовка пробного запуска на C04.3

Из корня репозитория в Python 3.12 с PyTorch 2.8.0 и tokenizers 0.21.4:

```sh
python -m scripts.c05_pilot check
```

На CPU проверены три контрольные суммы шардов, конфигурация модели, фактический артефакт токенизатора, его служебные роли и совпадение версии и размера словаря с C04. Конфигурация `configs/c05-pilot.json` использует 32 768 ID, все 20 слоёв и 968 968 192 параметра. Правое дополнение PAD=0, исключённые цели обозначаются −100. На полных шардах проверены сдвиг на одну позицию, число целей и сохранение всех переходов при сокращении окна с перекрытием на один ID.

| Шард | Форма контрольного CPU-пакета | Целей |
|---|---:|---:|
| train | [23, 251] | 3235 |
| validation | [16, 234] | 2232 |
| test (только проверка формата) | [16, 245] | 2521 |

На строках [1,3,2] и [1,2] цели после дополнения равны [3,2,−100] и [2,−100,−100]. Для заданных вручную логитов вероятности трёх правильных ответов — 1/2, 1/4 и 2/5. Средняя FP32 cross-entropy на CPU составила 0,998577436, аналитически 0,998577425, абсолютное расхождение 1,13 × 10⁻⁸ при допуске 10⁻⁶. Проверка использует только тензоры данных и контрольные логиты.

### После уточнения RTX и отдельной команды на GPU

1. Записать модель и доступную VRAM, версию драйвера из `nvidia-smi`, RAM, ОС, коммит, версии Python, PyTorch и CUDA. Установить совместимую CUDA-сборку PyTorch 2.8.0, tokenizers 0.21.4 и для Windows psutil 7.1.0. Проверить доступность CUDA, native BF16 и конечный результат реальной операции. Команда проверки:

   ```sh
   python -c "import torch; assert torch.cuda.is_available() and torch.cuda.is_bf16_supported(including_emulation=False); a=torch.ones((64,64),device='cuda',dtype=torch.bfloat16); b=a@a; assert b.dtype==torch.bfloat16 and (b==64).all(); print(torch.cuda.get_device_name(),torch.cuda.mem_get_info(),torch.__version__,torch.version.cuda)"
   ```

2. Сопоставить свободную VRAM с минимумом порядка 14,44 ГиБ на FP32 веса, градиенты и два момента AdamW, плюс активации, буферы и резерв CUDA. Начальная точка для карты с достаточным запасом — длина 32, микропакет 1, накопление 1. Если постоянная часть не помещается, потребуется отдельная конфигурация с offload или другая карта. Эта реализация хранит модель и AdamW на GPU. При наличии запаса сначала поднимать длину (64, 128, до фактических длин пилота), затем микропакет. Сравнивать при одинаковой конфигурации данных, учитывать первый шаг с созданием состояний. Накопление выбирать для нужного числа целей за обновление, взвешивание идёт по общей сумме целей. После измерений оставить запас для колебаний памяти.
3. Будущая команда для **примера стартового профиля** из пункта 2:

   ```sh
   python -m scripts.c05_pilot train --length 32 --microbatch 1 --accumulate 1 --output runs/c05-rtx
   ```

   Предложены два шага с постоянным LR 1e-4, AdamW, FP32-параметрами и моментами, BF16 autocast, seed 42. Логировать stdout. Каждый шаг печатает loss, число целей, время, скорость, пики allocated/reserved VRAM PyTorch и пиковый RSS процесса. Дополнительно снимать память устройства через `nvidia-smi` для оценки системного резерва. В конце вычисляется loss по validation. Выборка test зарезервирована для C06.
4. Задать каталог на локальном диске. При записи каждого завершённого шага учитывать примерно 11,6 ГБ на веса и моменты и место под вторую временную копию. Интервал задаёт `checkpoint_every`. Читаемая временная точка атомарно заменяет latest.pt. Для продолжения прерванного запуска повторить команду с теми же параметрами и `--resume`. Сохраняются номер шага, число целей, позиция в фиксированном порядке чтения, RNG, веса, оптимизатор, конфигурация и хеш манифеста. Постоянный LR записан в конфигурации. Сравнение непрерывного и возобновлённого обучения и фактические пики памяти предстоят на согласованной машине.
