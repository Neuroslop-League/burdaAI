# C07.5. Протокол сравнения CPU FP32

До первого сравнения устанавливаем максимальную абсолютную ошибку 1e-3 по всем элементам матрицы логитов, без относительного допуска. Проверяем четыре последовательных префикса одного запроса с BOS, на каждом требуем точного совпадения greedy ID (первый индекс максимума), конечности всех значений и совпадения формы. Эталон — Python Decoder.eval() под inference_mode, кандидат — Rust CPU FP32. Оба читают одни и те же неквантованные синтетические веса полной формы C01 и общий токенизатор. Остановку по EOS и границе окна проверяем отдельно от численного допуска.

## Сборка и запуск из чистого окружения

Требуются 64-битный little-endian CPU, Rust с Cargo, инструментальная цепочка C для зависимости Oniguruma и комплект reference-f32 C07.1. Сборка работает без установки PyTorch. Из корня репозитория:

```sh
cargo test --locked --manifest-path rust/Cargo.toml
cargo build --locked --release --manifest-path rust/Cargo.toml --bin burda-generate
rust/target/release/burda-generate --bundle /path/to/bundle --device cpu --placement cpu --text 'Привет, мир!' --max-new-tokens 4
```

CLI печатает декодированное продолжение. Он добавляет BOS к запросу, обрабатывает один полный префикс за шаг и берёт первый индекс максимального логита. EOS завершает генерацию, в вывод попадают только сгенерированные обычные токены. Бюджет ограничивается свободными позициями окна. При ошибке проверить профиль reference-f32, совпадение SHA-256 и конфигурации C02, затем длину запроса вместе с BOS. Неподдерживаемые значения устройства и размещения отклоняются. Для диагностики численной ошибки можно передать --trace-dir с новым путём: на диск будут записаны полные little-endian FP32 логиты каждого шага.

## Воспроизведение Python → Rust

На проверочной машине установить Python 3.12 и зависимости. Для диагностического прогона подготовить не менее 8 ГиБ свободного диска. Первый вызов создаёт новый рабочий каталог, экспортирует один синтетический комплект C01 (seed 42) и повторно читает его для эталона. Второй запускает Rust CLI с тем же текстом, сравнивает все позиции и весь словарь на каждом шаге.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install torch==2.8.0 tokenizers==0.21.4 safetensors==0.6.2 numpy==2.2.6
.venv/bin/python -m scripts.check_c07_cpu reference /tmp/burda-c075
.venv/bin/python -m scripts.check_c07_cpu compare /tmp/burda-c075
```

## Результат CPU-сверки для C06

Apple M1, 8 ГиБ общей RAM, macOS 26.7.1, Python 3.12.5 и rustc 1.100.0. Rust использует ndarray 0.16.1 (matrixmultiply 0.3.11), safetensors 0.6.2 и tokenizers 0.21.4. Идентификаторы запроса с BOS — [1, 568, 3546, 378, 14, 5807, 3]. SHA-256 файла весов: `653d5fd424752f283f91f4ea354ad59f2decd0b0bd49204afae6891ddac5f433`.

Файл весов занимает 3 875 890 624 байта. Загрузчик держит один буфер с весами; матрицы используют представления этого буфера. Дополнительная память выделяется под активации и полную матрицу логитов. Для четырёх коротких префиксов macOS сообщила пик RSS процесса Rust 2 073 935 872 байта. RSS отражает резидентные страницы в этом прогоне; для планирования учитывать весь буфер весов, активации, библиотеки и рабочую память ОС. Вычисления целиком на CPU. Профиль 1 ГБ VRAM, форматы 4 бит и сценарий 256+64 рассматриваются после приёмки CPU-этапа.

Тест цикла генерации подставляет последовательность из обычного ID и EOS и проверяет точное число вызовов. Отдельные случаи длины 4095, 4096 и 4097 проверяют последний свободный слот, остановку на заполненном окне и ошибку переполнения соответственно. CLI с комплектом fixtures/c07-v1 завершился с ошибкой unsupported profile.
