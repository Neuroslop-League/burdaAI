# Языковой стек burdaAI

Python отвечает за обучение и исследования, Rust — за эксплуатацию и системную инфраструктуру, CUDA — за специализированные вычисления на совместимых GPU.

| Компонент | Технология | Зона ответственности |
| --- | --- | --- |
| Transformer | Python, PyTorch | Эталонная архитектура, прямой и обратный проходы, проверки C01 |
| Training Engine и checkpoints | Python, PyTorch | Обучение с нуля, fine-tuning, оптимизаторы, гиперпараметры, мониторинг и восстановление |
| Dataset Pipeline | Python | Очистка и обработка корпусов, токенизация, подготовка и проверка выборок |
| Evaluation | Python | Оценка качества, сравнение весов и эксперименты |
| Tokenizer | Python / Rust | Python используется для подготовки и проверки артефакта. Rust загружает его при инференсе и может реализовать обработку запросов по тому же контракту |
| Inference Engine | Rust | Загрузка весов, генерация, управление RAM и VRAM, размещение CPU/GPU |
| KV-cache и batching | Rust | Инкрементальная генерация, управление памятью и пакетами запросов при необходимости |
| GPU Runtime | Rust + CUDA | Выбор устройства, вызов готовых вычислительных библиотек, CUDA для совместимых карт |
| CLI и API Server | Rust | Запуск модели, предобработка запросов, обслуживание и выдача результатов |

PyTorch — основной инструмент для модели и обучения. Hugging Face и NumPy можно использовать для данных, токенизации, представления артефактов и экспериментов. Для мониторинга C05 выбирает TensorBoard или Weights & Biases по потребностям запуска. Версии библиотек фиксируются вместе с конфигурацией окружения.

## Передача модели из Python в Rust

1. Python сохраняет контрольную точку для восстановления обучения. Она включает веса и состояние обучения по [C05](training.md).
2. Экспорт из выбранной контрольной точки формирует отдельный комплект инференса. В нём есть матрицы весов, конфигурация архитектуры, токенизатор и манифест с версиями и контрольными суммами. Эталонные веса хранятся в Safetensors F32. Имена, формы, порядок осей, общая матрица и правила проверки манифеста зафиксированы в [схеме C07.1](inference-bundle.md). Для квантованного варианта дополнительно фиксируются схема упаковки, группа и параметры восстановления значений.
3. Rust проверяет версию архитектуры, схемы, идентификатор и размеры словаря, соответствие тензоров и целостность артефактов до запуска. Общая матрица embedding и выходной проекции хранится однажды. Загрузчик выдаёт понятную ошибку при несовместимости.
4. Python и Rust проверяются по одному артефакту токенизатора и общим примерам с точным совпадением ID. Для одного комплекта неквантованных весов короткий детерминированный прогон проверяет логиты в допуске, определённом до замера. Квантованный комплект отдельно проходит порог качества C06.

## GPU и ограниченные ресурсы

Обязательная проверка Rust CLI выполняется на Mac владельца. Для дополнительного профиля **1 ГиБ VRAM** предусмотрено измеряемое гибридное размещение CPU/GPU. При выборе backend проверяются конкретная карта, драйвер, необходимые операции и пик памяти. Наличие CUDA проверяется на выбранной конфигурации. При несовместимости нужно подобрать доступный вычислительный backend или согласовать другую эталонную карту в рамках того же лимита. CUDA-совместимость сама по себе не подтверждает поддержку профиля.

Сначала использовать и измерить готовые библиотеки. Собственные CUDA-ядра и вычислительные компоненты рассматриваются только при воспроизводимом узком месте, если доступные реализации не закрывают требование и ожидаемый выигрыш оправдывает поддержку. KV-cache и batching проверяются отдельно. Минимальная генерация v1 использует один запрос и может работать с полным префиксом.

## Правила выбора технологии

- Python используется там, где нужны зрелые ML-инструменты. Rust используется там, где выигрывают производительность, контроль памяти или надёжность системной части.
- Проверенные библиотеки переиспользуются. Разработка аналогов PyTorch, CUDA или собственных вычислительных движков требует отдельного технического обоснования.
- Форматы весов, конфигураций и токенизатора согласуются для обоих языков. Изменение схемы или границ ответственности документируется с причиной и оценкой совместимости.
- Решения об оптимизации оцениваются по скорости, RAM и VRAM, сложности внедрения и стоимости поддержки на целевой конфигурации.
