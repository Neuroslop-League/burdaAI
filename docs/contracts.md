# Контракты разработки burdaAI

[README](../README.md) содержит утверждённые параметры модели и обучения. Эти контракты определяют работы, интерфейсы между исполнителями и требования к приёмке. Предлагаемые интерфейсы становятся обязательными после согласования в соответствующей задаче.

## Назначение и приёмка

- Исполнители и принимающие пока не назначены. Перед началом контракта менеджер фиксирует исполнителя и принимающего в задаче проекта. Для отдельных задач можно назначить разных исполнителей.
- Статусы задач: **готова к работе**, **ожидает зависимости**, **в работе**, **на приёмке**, **принята**. Готовность означает, что работу можно начать. Текущие статусы отражают план, реализация и результаты проверок в репозитории пока отсутствуют.
- На приёмку исполнитель передаёт ссылку на PR или версию артефакта, команду проверки, её результат и известные отклонения. Для решения без реализации достаточно записи о согласовании с обоснованием.
- Контракт принят, когда приняты все его задачи и принимающий проверил передачу результата потребителю. Если работа продолжается с открытой зависимостью, менеджер фиксирует допустимый объём работ, риск и условие закрытия зависимости.

**Вход** — утверждённые параметры из README и требования к интерфейсу словаря для C02. **Результат** — [спецификация модели v1](model-spec.md) с формами тензоров и правилами вычислений для C03, C05 и C06.

## Порядок передачи в работу

C01 принят. Для начала доступны C02.1, C03.1 и C04.1. После получения схемы конкретного словаря из C02.1 можно определить формат примеров C04.2. Реализацию декодера C03 и сборку данных C04 можно вести параллельно. C05.1 можно начать, как только известно целевое оборудование. Обучающий цикл C05.2 требует принятых декодера и данных. Планирование оценки C06.1 начинается после согласования источников и разбиения, а полный прогон C06.2 требует принятого пробного запуска и утверждённого протокола.
