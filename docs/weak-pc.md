# C07.6. Профиль дискретной карты с 1 ГиБ VRAM

## Формат и размещение

Вход конвертера — принятый комплект reference-f32. После проверки хешей и размеров скрипт переносит C01 в GGUF для llama.cpp b5046 (ревизия 74d4f5b041ad837153b0e90fc864b8290e01d8d5). Матрицы Q/K уже используют соседние координаты RoPE. Единственная token_embd.weight обслуживает вход и выход, нормы остаются F32. GGUF хранит идентификатор C02 и SHA-256 исходных весов. Rust выполняет токенизацию C02 и передаёт ID отдельному процессу с готовым backend GGML. Старые команды для Rust FP32 продолжают работать.

Сравнивались блоки по 32 веса. Q4_0 хранит 16 байтов кодов и один FP16-масштаб (4,5 бита/вес); Q4_1 добавляет FP16-смещение (5 бит/вес). По фиксированным префиксам считаются последние логиты по всем 32 768 ID относительно сохранённых Rust CPU FP32. Это численная характеристика на синтетических весах. Порог качества на обученной модели относится к C06.

| Размещение 20 блоков | Веса блоков на GPU, Q4_0 / Q4_1, МиБ | K/V F32 на GPU при T=320, МиБ | Обмен |
|---|---:|---:|---|
| 0, все на CPU | 0 / 0 | 0 | CPU-контроль, без GPU |
| Последние 8 на GPU | 193,62 / 215,12 | 10 | CPU выполняет embedding и первые 12 блоков; после последних 8 результат возвращается на CPU для финальной проекции |
| Все 20 на GPU | 484,06 / 537,81 | 25 | CPU сохраняет embedding и выходную проекцию, меньше вычислений слоёв на CPU |

Для первого аппаратного прогона выбраны **Q4_0 и последние 8 блоков на Vulkan**. На 320 позициях сырые веса и K/V этих блоков требуют около 204 МиБ. В этот расчёт не входят выравнивание, временные тензоры графа, шейдеры, драйвер и экран. Окончательное размещение выбирается на целевой карте по пикам памяти и скорости. Сценарий C01.4 обрабатывает полный префикс заново на каждом шаге; внутренний буфер K/V библиотеки очищается перед каждым forward. Контекст 320, физический микропакет до 64, один запрос, четыре CPU-потока.

## Сборка и CPU-сверка

Из корня проекта, в окружении C07.5 (Python 3.12, PyTorch 2.8.0, safetensors 0.6.2, numpy 2.2.6, tokenizers 0.21.4):

```sh
python -m pip install gguf==0.17.1 psutil==7.1.0
git clone --depth 1 --branch b5046 https://github.com/ggml-org/llama.cpp.git /tmp/burda-llama
runtime/ggml/build.sh /tmp/burda-llama /tmp/burda-cpu-build cpu
cargo build --locked --release --manifest-path rust/Cargo.toml --bin burda-generate
# WORK содержит bundle/ и rust-logits/ из протокола C07.5.
for kind in F32 Q4_0 Q4_1; do
  python -m scripts.c07_gguf "$WORK/bundle" "$WORK/$kind.gguf" "$kind" || exit 1
done
python -m scripts.check_c07_quant "$WORK" /tmp/burda-cpu-build/bin/burda-ggml "$WORK/F32.gguf" "$WORK/Q4_0.gguf" "$WORK/Q4_1.gguf"
```

## Аппаратная приёмка

Предлагаемая воспроизводимая платформа для замера — Linux x86-64, одна дискретная AMD amdgpu с 1 ГиБ выделенной памяти, рабочий Vulkan ICD и доступные счётчики sysfs. Нужны Git, CMake, C++17, Vulkan SDK/headers, загрузчик Vulkan и glslc. На машине приёмки зафиксировать модель, PCI-адрес, драйвер, вулкановский ICD (`vulkaninfo --summary`), CPU, RAM и ОС. Передать туда выбранный GGUF и репозиторий с C02. На другой ОС или у другого вендора потребуется соответствующий источник показаний VRAM.

```sh
runtime/ggml/build.sh /tmp/burda-llama /tmp/burda-vk-build vulkan
cargo build --locked --release --manifest-path rust/Cargo.toml --bin burda-generate
rust/target/release/burda-generate --gguf "$WORK/Q4_0.gguf" --runner /tmp/burda-vk-build/bin/burda-ggml --tokenizer artifacts/c02-v1 --device vulkan --placement last:8 --text 'Привет, мир!' --max-new-tokens 4
python -m scripts.check_c07_1gib /tmp/burda-vk-build/bin/burda-ggml "$WORK/Q4_0.gguf" --drm /sys/class/drm/card0 --log /tmp/burda-vk-run.log > /tmp/burda-vk-report.json
```

Указать фактический cardN. Команда требует 256 фиксированных ID (включая BOS) и выдачи 64 ID с отключённой ранней остановкой. Лог содержит размещение буферов GGML и событие завершённой операции MUL_MAT с буфером дискретного GPU; отсутствие свидетельства завершает прогон ошибкой. Отчёт содержит SHA-256 GGUF, PCI-адрес, 64 ID, холодный TTFT от старта backend (включая загрузку), тёплый TTFT после создания контекста и скорость следующих 63 токенов. Для VRAM записываются исходная занятость всей карты и максимальная наблюдавшаяся занятость; для RAM — выборочный RSS процесса backend и пиковый RSS ядра Linux по завершённому дочернему процессу. Период опроса 20 мс, более короткие пики могут быть пропущены. При ошибке выделения памяти приложить лог и повторить отдельный диагностический прогон с меньшим числом GPU-блоков. Приёмочный профиль и реально выполненное размещение фиксировать раздельно.

## Результаты численной сверки на CPU

Синтетический FP32-комплект C07.5, SHA-256 весов `653d5fd424752f283f91f4ea354ad59f2decd0b0bd49204afae6891ddac5f433`. Во всех трёх GGUF на четырёх принудительно одинаковых префиксах использованы внутренние K/V F32. Сравнивались 131 072 значения последней позиции. RMSE весов считается по всем элементам матриц (нормы хранятся без потерь).

| GGUF | Байт файла | RMSE весов | RMSE логитов | max abs логитов | Совпадения greedy |
|---|---:|---:|---:|---:|---:|
| F32 | 3 877 516 576 | 0 | 0,000002868 | 0,00001359 | 4/4 |
| Q4_0 | 546 977 056 | 0,00171787 | 0,53450 | 2,33769 | 1/4 |
| Q4_1 | 607 532 320 | 0,00156417 | 0,50115 | 2,50643 | 1/4 |

Контроль GGUF F32 укладывается в допуск CPU C07.5 (1e−3). Q4_1 уменьшил среднеквадратичную ошибку, но занял на 60 555 264 байта больше и дал ту же частоту совпадения greedy. Приоритет компактности для первого аппаратного прогона оправдывает Q4_0. Статистика четырёх префиксов не устанавливает качество сжатия обученного декодера.

Локальная проверка выполнена на Apple M1 с интегрированным GPU, macOS 26.7.1, CPU-сборка GGML. Rust CLI с Q4_0 выдал четыре ID; запрос Vulkan к сборке без GPU завершился ошибкой. Дискретной карты 1 ГиБ на этой машине нет. Сборка и запуск Vulkan на целевом Linux, подтверждение GPU-операции, замеры VRAM, RAM, TTFT и токенов/с на сценарии 256+64 остаются открытыми до аппаратной приёмки.
