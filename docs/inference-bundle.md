# C07.1. Комплект инференса Python → Rust

## Контейнер и версии

Схема 1 задаёт каталог с пятью файлами. Точка входа — manifest.json (UTF-8 JSON). Обязательные поля: целое schema_version=1, profile, строка tokenizer_id и объект files. Ключи files — ровно четыре фиксированных имени ниже, значения содержат целое bytes и sha256 (64 строчные шестнадцатеричные цифры от всех байтов файла). Проверка охватывает точное содержимое вместе с заголовками и переводами строк. Эталонный профиль называется reference-f32; loader-fixture доступен только при явном запуске тестов. architecture_version внутри config.json версионирует математику C01 независимо от схемы каталога. Хеш самого манифеста можно закрепить во внешнем описании релиза. Внутренние суммы обеспечивают контроль целостности при наличии доверенного манифеста.

| Файл | Содержание |
|---|---|
| config.json | Все поля Config Python в UTF-8 JSON с числами JSON и строковым tokenizer_id |
| model.safetensors | Один именованный плотный тензор на ключ state_dict, F32 |
| tokenizer.json | Общий файл Hugging Face Tokenizers |
| tokenizer-manifest.json | Манифест C02 под фиксированным именем комплекта, включая внутренний SHA-256 tokenizer.json, размер словаря и special_tokens |

Для эталона выбран Safetensors. Python и Rust читают один контейнер, заголовок даёт тип, размеры и диапазоны байтов до создания тензоров. Чтение допускает mmap и не требует десериализации исполняемых объектов. Формат хранит плотные массивы без strides; разделение параметров описывает схема модели. Контроль целостности и связь с токенизатором обеспечивает внешний манифест. Веса FP32 модели с текущим C02 занимают 3 875 872 768 байт плюс заголовок. Контейнер пригоден для численного эталона C07.2/3. Квантованный выпуск потребует отдельного профиля с правилами упаковки. [Спецификация Safetensors](https://github.com/huggingface/safetensors#format)

## Конфигурация эталона

Версия 1 требует num_layers=20, hidden_size=2048, intermediate_size=5632, num_attention_heads=16, num_key_value_heads=4, max_sequence_length=4096, rope_theta=10000, rms_norm_eps=1e-5, initializer_std=0.02. Имена и типы соответствуют [Config](../burdaai/decoder.py) и [C01](model-spec.md). vocab_size — положительное целое из C02. Для принятого словаря V=32768, PAD=0, BOS=1, EOS=2, SHA-256 tokenizer.json равен `04efc216e2a03fb974f1420b77c5d631f01d4c3edbaa4b628808b64d96f30413`, tokenizer_id равен `burda-bpe-v1-sha256-04efc216e2a03fb974f1420b77c5d631f01d4c3edbaa4b628808b64d96f30413`. Сопоставить все три копии идентификатора (config, manifest, tokenizer-manifest) и при наличии ожидаемую версию вызывающей стороны. [Манифест C02](../artifacts/c02-v1/manifest.json)

## Каталог тензоров

Все значения — IEEE 754 binary32, little-endian, row-major (последняя ось непрерывна). Для каждой проекции матрица W задаётся в порядке [выход, вход], результат равен x·Wᵀ. Порядок ключей и физическое расположение тензоров определяет заголовок Safetensors. Суффикс каждого имени в таблице буквальный; i — десятичный индекс без ведущих нулей, 0…19.

| Имя state_dict и ключ Safetensors | Форма C01 | Оси |
|---|---|---|
| embedding.weight | [V,2048] | ID, скрытая компонента |
| blocks.i.attn_norm.weight | [2048] | скрытая компонента перед вниманием |
| blocks.i.attn.q.weight | [2048,2048] | Q-голова × компонента, скрытый вход |
| blocks.i.attn.k.weight | [512,2048] | KV-голова × компонента, скрытый вход |
| blocks.i.attn.v.weight | [512,2048] | KV-голова × компонента, скрытый вход |
| blocks.i.attn.o.weight | [2048,2048] | скрытый выход, Q-голова × компонента |
| blocks.i.ffn_norm.weight | [2048] | скрытая компонента перед FFN |
| blocks.i.gate.weight | [5632,2048] | компонента вентиля, скрытый вход |
| blocks.i.up.weight | [5632,2048] | промежуточная компонента, скрытый вход |
| blocks.i.down.weight | [2048,5632] | скрытый выход, промежуточная компонента |
| norm.weight | [2048] | скрытая компонента финальной RMSNorm |

На объединённой оси индекс равен head × 128 + component; KV-голова для Q-головы h равна floor(h/4). Вращение соседних компонент Q/K, порядок residual, RMSNorm и SwiGLU заданы C01. RoPE вычисляется из конфигурации. Всего 9 × 20 + 2 = 182 тензора. Одна embedding.weight обслуживает lookup при входе и проекцию logits = rms_final(x)·Eᵀ. Rust использует одну область хранения E для обоих обращений. Дополнительный lm_head.weight, даже побайтово идентичный, нарушает схему.

## Проверки загрузчика C07.3

1. Разобрать манифест с отказом при дублирующихся JSON-ключах, неизвестной версии или профиле, лишнем/пропущенном имени файла, ошибочном типе, отрицательном размере или неверном digest. Открывать только фиксированные файлы внутри каталога. Сверить длину и SHA-256 до передачи содержимого backend.
2. Проверить обязательные поля и значения Config по C01, целочисленные положительные размеры, чётный размер головы и делимость размеров GQA. Сверить V, диапазон уникальных ID 0…V−1, специальные роли и идентификатор с токенизатором. Проверить внутренние file и sha256 из tokenizer-manifest. Размер словаря сам по себе недостаточен.
3. Разобрать заголовок библиотекой Safetensors. До выделения памяти проверить ожидаемый набор имён, ранг, каждую ось и F32. Считать размер как произведение осей × 4 с контролем переполнения. Повреждённые, перекрывающиеся, выходящие за файл диапазоны, несогласованные длины и неверная раскладка заголовка ведут к отказу. Ошибка указывает файл и ключ. Частично загруженная модель не передаётся инференсу.

## Контрольный комплект

[Пример манифеста и четыре файла](../fixtures/c07-v1/manifest.json) самодостаточны. Профиль loader-fixture имеет L=1, H=8, F=12, Q=4, KV=2, V=8, D=2; тестовый WordLevel задаёт свои восемь ID. Только тестовый режим разрешает эти размеры и tokenizer_id. Ожидаемые формы выводятся из той же таблицы заменой ширин: выход K/V равен KV × D. Сортировка имён по ASCII задаёт номер k с нуля; значение плоского элемента j равно 1000k+j. В Rust проверить все 568 значений 11 тензоров, включая порядок строк прямоугольных K, V, gate и down. В production-режиме этот же комплект должен получить отказ по profile.

Проверка C07.1 в Python 3.12 с CPU PyTorch 2.8.0:

```sh
python -m pip install safetensors==0.6.2 numpy==2.2.6
python -m scripts.check_c07_bundle
```

Фактический результат: для C01 на meta совпали имена, формы и типы всех 182 записей state_dict (968 968 192 элемента). Для контрольного комплекта проверены суммы файлов и прочитаны все 11 тензоров (568 элементов). Реальные веса для сверки схемы не требуются.

## C07.2–3. Экспорт и загрузка

Из корня проекта экспортировать доверенный локальный checkpoint в новый каталог. Python 3.12, CPU PyTorch 2.8.0, numpy 2.2.6 и tokenizers 0.21.4. Экспортёр принимает checkpoint C03 (config/state_dict) и C05 (signature.config.model/model). Проверяет FP32 и точные формы по Python Decoder, пишет плотные матрицы по одной и публикует каталог после формирования всех хешей. Для полного комплекта предусмотреть 3,9 ГБ на диске. Загрузчик Rust проверяет комплект и предоставляет заимствованные представления тензоров поверх одного буфера в RAM.

```sh
python -m scripts.c07_export checkpoint.pt output/bundle
cargo run --locked --release --manifest-path rust/Cargo.toml -- output/bundle
```

Для приёмки на синтетическом checkpoint полный двухформатный тест занимает около 7,3 ГиБ диска. Аргумент теста — новый каталог. Проверка Python дополнительно использует safetensors 0.6.2 для независимого чтения всех значений.

```sh
python -m scripts.check_c07_export /tmp/burda-c07-test
cargo test --locked --manifest-path rust/Cargo.toml
cargo run --locked --release --manifest-path rust/Cargo.toml -- fixtures/c07-v1 --fixture
cargo run --locked --release --manifest-path rust/Cargo.toml -- /tmp/burda-c07-test/c05
```

При проверке манифесты обоих экспортов совпали побайтно; SHA-256 весов — `7fee2a2003dd918e39343d44c4f190864222639fc3f6a38c198c2b2f2255b57a`. Rust прочитал 182 тензора полной размерности. В fixture проверены все 568 значений и отказ на неверном профиле, версии, повреждении файла, подмене токенизатора и перестановке осей с заново вычисленным хешем.

## C07.4. Текст запроса в Rust

`TextTokenizer::load_c02(directory)` загружает C02 непосредственно из каталога с manifest.json и tokenizer.json. При загрузке комплекта reference-f32 тот же код получает проверенные байты токенизатора из Bundle. Метод `encode(text)` возвращает обычные ID, в том числе для текста вида `<|bos|>`. Вызывающий код явно вставляет служебные ID. Метод `decode(ids, skip_special)` сохраняет или пропускает их по флагу. Обе реализации используют Tokenizers 0.21.4.

Команды сверки из корня проекта:

```sh
cargo test --locked --manifest-path rust/Cargo.toml --test c02_golden
python scripts/c02_golden.py
```

Каждый тест дважды открывает общий артефакт и сверяет все 14 пар из artifacts/c02-v1/golden.json. Для каждой строки проверяются точные ID, диапазон обычных токенов, восстановление исходного текста и оба режима декодирования последовательности BOS + ID текста + EOS + PAD.
