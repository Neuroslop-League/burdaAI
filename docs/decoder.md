# C03. Декодер

Цель — реализовать на Python и PyTorch эталонный прямой проход для обучения и проверки выпуска. [C01](model-spec.md) задаёт математические операции, конфигурацию и семантику масок. C03 передаёт модель, конфигурацию, инструкции по проверке и сведения о формате весов.

## Интерфейсы и границы

| Граница | Ожидаемое поведение |
| --- | --- |
| Создание модели | Проверить версию архитектуры и фиксированные размеры C01. Размер словаря и идентификатор токенизатора передаются как параметры |
| Загрузка весов | Сверить версию конфигурации, обязательные тензоры, их формы и связку с токенизатором. Несовместимые веса отклоняются до запуска |
| Прямой проход | ID int32 или int64 и необязательная булева маска правого дополнения на входе. Логиты `[B, T, vocab_size]` на выходе |
| Вычисления | 20 блоков pre-RMSNorm с RoPE, causal GQA и SwiGLU, затем финальная нормализация и общая матрица embedding и выходной проекции |
| Интеграция с C05 | Прямой проход поддерживает обратное распространение. Цели, функция потерь и шаг оптимизатора находятся в C05 |
| Интеграция с C06 | Эталонные логиты используются для проверки генерации и оптимизаций. Профиль на 1 ГБ VRAM проверяется в C06 |

Формат имён тензоров, способ загрузки, интерфейс ошибок, backend и конкретные команды фиксируются в реализации. Смена вычислительного backend допускается при сохранении семантики C01 и прохождении соответствующих проверок.

## Задачи и проверка

- **C03.1.** Собрать модель по конфигурации реального размера и проверить 20 слоёв, формы Q/K/V/O, FFN, логитов и число уникальных параметров. Убедиться, что общая матрица входа и выхода хранится как один обучаемый параметр и получает градиенты.
- **C03.2.** Проверить малый FP32-эталон GQA с различимыми KV-головами, единичное действие RoPE на позиции 0, маску, порядок голов и численное соответствие поддерживаемого backend. Для проверки изменения будущих токенов сравнивать только позиции общего префикса. Допуски утверждаются в отчёте C03.2 до проверки. Для каждого допуска указать тип данных, эталон и метрику ошибки.
- **C03.3.** Проверить длины 1 и 4096, пакет с правым дополнением, нули в логитах дополнения, конечность логитов и отказ на входах за границами C01. Сопоставить логиты действительных позиций короткой строки отдельно и в пакете. Сохранить и загрузить тестовые веса, затем повторить прямой проход.

Для передачи C05 приложить версии окружения, команды, результаты проверок и пример загрузки с условным словарём. Проверка максимального окна выполняется на оборудовании, где помещается эталонный прямой проход.

### Локальная проверка C03.1

Из корня репозитория выполнить:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install torch==2.8.0
.venv/bin/python -m scripts.check_c03
```

`Config.load(path)` читает JSON конфигурации, `Decoder(config)(input_ids, attention_mask)` возвращает логиты. Контрольная конфигурация находится в `configs/c03-fixture.json`. Проверка использует CPU, BF16 и реальный causal SDPA с явно сгруппированными KV-головами. Для проверки градиента общей матрицы остальные параметры заморожены только в контрольном запуске. Численное сравнение внимания с независимым эталоном относится к C03.2.

### C03.2. Критерии численного сравнения

До запуска фиксируем backend PyTorch CPU FP32, seed 42 и максимальную абсолютную ошибку по элементам без относительного допуска. Для выходов 16 голов причинного GQA после RoPE (включая правое дополнение) и логитов общего префикса двух входов одинаковой длины порог равен 1e-5. Для поворота Q и K на позиции 0 и для соответствия голов в контрольном случае с одним ключом требуется точное совпадение. Эталон считает углы по соседним парам компонент и отдельно вычисляет softmax и взвешенную сумму для каждой головы и разрешённого префикса.
