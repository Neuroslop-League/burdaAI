# C02. Токенизатор

Цель v1 — кодировать русский и английский текст единым словарём. Этот документ задаёт интерфейс и процедуру выбора. Конкретный словарь и артефакт выпускаются в C02.2.

## Интерфейс и конфигурация

| Операция или поле | Контракт |
| --- | --- |
| Кодирование | Строка Unicode преобразуется в последовательность целочисленных ID. Автоматическое добавление специальных токенов отключено по умолчанию |
| Декодирование | Последовательность ID преобразуется в строку. Пропуск специальных токенов управляется явной настройкой |
| `tokenizer_id` | Неизменяемый идентификатор версии артефакта по [C01](model-spec.md) |
| `vocab_size` | Положительное целое. Допустимые ID образуют непрерывный диапазон от 0 до `vocab_size - 1` |
| `special_tokens` | Отображение ролей в ID. Для v1 предлагаются отдельные роли BOS, EOS и PAD. Конкретные ID определяет C02.1 |
| Нормализация | Правила Unicode, регистра и проб, включая обработку пустого ввода, фиксируются вместе с артефактом. Изменение правил образует новую версию |
| Максимальная длина | Токенизатор возвращает полную последовательность. C04 и C06 применяют свои правила обработки лимита модели в 4096 токенов |

Литеральный текст, похожий на обозначение служебного токена, кодируется как обычный текст. Служебные ID вставляет вызывающая сторона. C04 использует их для границ документа и дополнения пакетов. C06 применяет те же правила при подготовке входа и завершении генерации.

## Выбор и выпуск

- **C02.1.** Сравнить готовый токенизатор с вариантом собственного обучения на одном фиксированном наборе русского, английского и смешанного текста. Измерить токены на байт и долю примеров выше лимита контекста, проверить восстановление текста по правилам нормализации, обработку редких символов и доступность артефакта на целевой платформе. Отдельно показать результаты по языкам и влияние размера словаря на веса и логиты по C01. Зафиксировать метод, размер словаря, служебные ID и причины выбора.
- **C02.2.** Передать файл токенизатора, манифест, контрольную сумму, версию загрузчика и инструкцию. Для готового артефакта указать источник, версию и условия использования. Для собственного также указать входной корпус, конфигурацию и команду обучения. Корпус для обучения токенизатора не включает отложенные выборки C04.
- **C02.3.** Проверить точные последовательности ID после повторной загрузки. Включить кириллицу, латиницу, смешанный текст, комбинируемые символы, эмодзи, переводы строк, повторные пробелы, пустую строку и литералы служебных токенов. Проверить диапазон ID, вставку специальных токенов и декодирование по утверждённым правилам.

Приёмка требует артефакта, команды проверки и эталонных примеров. C04 и C06 получают одну и ту же версию. Изменение отображения текста в ID требует пересборки данных и проверки совместимости с весами.

## C02.1. Предварительное решение

Предпочтительный кандидат — собственный byte-level BPE на русском и английском, обученный через Hugging Face Tokenizers. Начальный целевой размер — 32 768 ID, включая служебные. Для сравнения использовать готовый GPT-2 BPE как контрольную точку. Выбор кандидата основан на контроле размера словаря, возможности обучать его на двух целевых языках и общем артефакте для Python и Rust. Эффективность кодирования пока предстоит измерить. [Hugging Face Tokenizers](https://www.huggingface.co/docs/tokenizers/python/latest/api/reference.html) · [Определение словаря GPT-2](https://github.com/openai/tiktoken/blob/main/tiktoken_ext/openai_public.py)

| Вариант | Преимущества | Ограничения |
| --- | --- | --- |
| Собственный BPE, 32 768 ID | Контроль состава обучающей выборки, служебных ID и размера матрицы весов | Требуется согласованный корпус и воспроизводимое обучение токенизатора |
| Готовый GPT-2 BPE, 50 257 ID до адаптации | Доступная контрольная точка без обучения токенизатора | Добавление отдельных служебных ролей и проверка русского текста и совместимости с проектом |

По C01 каждый дополнительный ID добавляет 2048 параметров в общую матрицу embedding и проекции. Разница между 32 768 и 50 257 ID составляет 35 817 472 параметра, или около 71,6 МБ весов при двух байтах на параметр, до адаптации служебных ID.

### Предлагаемая схема собственного словаря

- Служебные ID: PAD = 0, BOS = 1, EOS = 2. ID обычных токенов занимают диапазон 3–32 767. Базовый алфавит содержит все 256 байтовых значений. Загружаемый артефакт проверяется на фактический размер и непрерывность ID.
- На входе допустим Unicode-текст. Исходное представление UTF-8 сохраняется без изменения регистра, Unicode-нормализации и искусственного добавления пробела. BOS, EOS и PAD вставляет вызывающий код. Строки, похожие на зарезервированные обозначения, должны кодироваться как обычный текст. Это требование проверяется в Python и Rust независимо от настроек библиотеки.
- Результат передаётся через общий файл `tokenizer.json` и манифест C01. `tokenizer_id` связывается с контрольной суммой файла. Для декодирования обычного текста контрольным результатом служит точное восстановление строки.

### Что требуется для приёмки решения

Согласовать первый репрезентативный набор русского и английского текста в C04.1. Из него выделить непересекающиеся выборки для обучения собственного кандидата и сравнения. Для каждого языка и смешанного текста записать число документов, байтов и токенов, отношение общего числа токенов к числу байтов и долю примеров длиннее 4096 токенов при одинаковых правилах подсчёта. Отдельно прогнать контрольные случаи Unicode, пробелов и служебных литералов. Опубликовать версии входов и библиотек, конфигурацию кандидатов, команду и результаты. До этих замеров решение предварительное.

### Набор для согласования в C02.1

Предлагается Universal Dependencies r2.15. Русская часть — энциклопедические тексты [Russian GSD](https://github.com/UniversalDependencies/UD_Russian-GSD/tree/47c45deefdcb3ac15e2f33e3093c8d10c1b6b36e), английская — веб-тексты пяти жанров [English EWT](https://github.com/UniversalDependencies/UD_English-EWT/tree/4dc8e10cf32352e11ab2c46e024b19853b91546e). Оба источника указывают CC BY-SA 4.0. При распространении текстов и адаптаций сохранять атрибуцию, ссылку на лицензию и сведения об изменениях, адаптации распространять на условиях той же лицензии.

Для обучения использовать строки `# text = ` только из train обоих источников. Для сравнения брать dev в исходном порядке, исключая предложения с точным совпадением в train. Test оставить для C04. Сохранять регистр и пробелы внутри строки. Для проверки лимита контекста дополнительно формировать блоки по 256 последовательных предложений через перевод строки, включая последний неполный блок. Для смешанной части чередовать русские и английские предложения dev до исчерпания меньшей части. Метрики одиночных предложений и блоков публиковать отдельно, учитывая BOS и EOS при проверке лимита C04.

Набор небольшой и открытый, но жанр связан с языком. Замеры характеризуют эти выборки. Смешанные блоки проверяют переключение языка и не представляют естественную двуязычную переписку.
